## **2. What would make your project different?**

I think there are three things that could make this project stand out.

### **A. Don't assume everyone has internet**

This is probably the most important design decision.

Imagine someone living in a remote village in Bhola or Patuakhali. Their mobile internet stops working during a cyclone.

Your application should not become useless.

Consider a layered communication system:

| Situation                         | Solution                                                   |
| --------------------------------- | ---------------------------------------------------------- |
| Internet available                | Full application                                           |
| Slow internet                     | Lightweight text-based interface                           |
| No internet                       | Cached shelters and emergency instructions                 |
| Mobile network available, no data | SMS alerts and emergency information                       |
| No mobile network                 | Local emergency information and community-based assistance |

You won't necessarily implement every communication method during the hackathon. But designing around this reality will make your project much stronger.

### **B. Make the application actionable**

A normal weather app says:

"Severe cyclone approaching your area."

Your application should say:

**আপনার এলাকার জরুরি সতর্কতা**

### **C. Include vulnerable people in the design**

Don't design only for someone who owns a smartphone and knows how to use Google Maps.

Think about:

- Elderly people who cannot walk long distances.
- People with disabilities who need accessible shelters.
- Families with infants.
- People who cannot read complex instructions.
- People who don't understand English.

Use Bangla as the primary language. Consider voice instructions and audio alerts too.

### **Suggested technology stack**

Since you already have experience with React, TypeScript and weather APIs, you have a useful starting point for understanding the technical side.&#x20;

| Component       | Technology                               |
| --------------- | ---------------------------------------- |
| Frontend        | React + TypeScript + Vite                |
| Styling         | Tailwind CSS                             |
| Maps            | Leaflet + OpenStreetMap                  |
| Backend         | Fastify or Node.js                       |
| Database        | Supabase / PostgreSQL                    |

| Location        | Browser Geolocation API                  |

One important point: use official, authoritative disaster warnings rather than generating your own cyclone predictions. You could investigate the Bangladesh Meteorological Department, Department of Disaster Management and relevant local authorities as information sources.

Also, shelter occupancy, food availability and road accessibility need verified updates. Don't present unverified information as real-time facts.

**Community SOS Network**

The system could:

- A resident's mobile interface.
- An emergency responder's dashboard.
